## 问题

1. **P1 群卡片先截断再脱敏，长私钥会泄漏。**
   src/presenter/task-card.ts:10 先 slice(-18000)，再 redact。私钥块超出窗口时 BEGIN 标记被截掉，
   剩余私钥正文直接进入群输出。定向复现 large_private_key_leaks=true。
   应对完整文本脱敏后再裁剪，并覆盖跨 streaming chunk 与截断边界。

2. **P1 /stop 只取消最近五条任务，遗漏正在运行的旧任务。**
   src/gateway.ts 的 /stop 使用 TaskManager.status；该查询 LIMIT 5 且包含终态任务。
   连续发送六个长任务，再 /stop，较早的 RUNNING 任务仍在执行。
   复现 oldest_task_after_stop=RUNNING。取消应独立查询当前 conversation 的全部非终态任务，
   保留 requester/Owner 校验，不能复用展示历史列表。

3. **P2 Owner 群聊没有写入摘要，load 失败时恢复上下文为空。**
   src/tasks/task-manager.ts:97 只保存 READ 或私聊摘要，Owner 群聊 WRITE 完全跳过。
   禁用 Fake ACP load capability，完成任务后重建进程，公开摘要长度为零。
   应按 profile 保存公开摘要，WRITE fallback 可复用 WRITE 历史，同时禁止它流入 READ。

4. **P2 发送最终卡片失败会留下 COMPLETED + error，并丢弃最终结果。**
   src/tasks/task-manager.ts:95 先 COMPLETED 再 finish；模拟 finish 的网络失败后，
   SQLite status=COMPLETED、error=SIMULATED_FINAL_DELIVERY_ERROR，catch 又显示 FAILED，
   且摘要尚未保存。应持久化最终结果、区分执行结果和回复交付状态，使重试无需重新执行改代码任务。

5. **P2 取消审批返回 selected/reject_once，而不是 ACP cancelled。**
   src/approvals/approval-manager.ts:42 对所有非 APPROVED 状态选择 reject_once。
   cancelTask 定向复现返回 selected/reject，违反 SDK Client.requestPermission 文档明确的
   “Client cancels turn MUST respond Cancelled”。取消/关闭与用户明确拒绝需要分别处理。

6. **P2 自动建仓库缺少落盘与注册之间的故障恢复。**
   src/repos/default-repo-service.ts:41 rename 目标目录后，才注册内存/写 managed_repos。
   用 SQLite trigger 模拟 INSERT 失败，再移除 trigger 重试，报 Default Repo id conflicts with configured Repo。
   重启后目标目录仍占用，无法自动创建/复用。应记录 durable 创建阶段并安全恢复/补全注册，
   防止生成无法绑定的孤儿仓库；不得覆盖或删除用户修改。
